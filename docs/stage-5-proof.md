## Gaps the screens found

Each gap is specified like a Stage 2 component and built from existing tokens only: no new colours, sizes or radii were needed, which is the real test of the foundations.

### Insight card

**Needed on:** Home. Home needed one sentence of meaning with its evidence. Card + chart could fake it, but every team would lay it out differently.

**Anatomy**

1. Icon tile 40 (category)
2. Sentence title with the number (type/title-sm)
3. Two comparison bars on one shared scale: this period vs last (color/chart/1 vs color/finance/spent)
4. Labels with amounts (type/amount/sm)
5. Optional: dismiss icon button, 'See breakdown' link

**States:** Default · Loading (skeleton) · Not enough data (hidden, never faked) · Dismissed (gone until next insight)

**Rule:** One insight on Home at a time. Always factual and neutral: 'less' and 'more', never 'better' or 'worse'.

### Upcoming bill row

**Needed on:** Home, Budget detail. Rent, EMIs and subscriptions are future money. The transaction row is past tense and has no due state.

**Anatomy**

1. Date block: day (type/amount/md) over month (type/label-sm) in color/surface/sunken, radius/md
2. Name + cadence (type/label-lg / type/body-sm)
3. Amount, right-aligned (type/amount/md)
4. Due tag: 'In 3 days' / 'Today' / 'Paid' (with check)
5. Optional: Mark paid

**States:** Upcoming · Due today (warning tag, not red) · Paid (success tag) · Missed ('Not paid yet', neutral + action)

**Rule:** Overdue bills are stated plainly with an action, never in danger colours: missing a date is information, not failure.

### Sync status line

**Needed on:** Home, Activity. Local-first means numbers can be minutes or hours old. The age of the data has to be visible wherever headroom is shown.

**Anatomy**

1. History icon (icon/size/xs)
2. 'Updated 5 min ago' (type/body-sm, color/text/secondary)
3. Refresh icon button (48 hit)
4. Spinner replaces the icon while syncing

**States:** Fresh (< 1h: shown only on pull) · Stale (> 1h: always shown) · Syncing · Failed (becomes an inline alert)

**Rule:** Relative time is allowed here (and only here) because it describes the data's age, not a transaction's date.

### Period summary

**Needed on:** Transactions list. Filters change what's in the list, so totals must recompute for exactly that set. Without a defined component, totals and lists drift apart.

**Anatomy**

1. Two or three cells: Spent, Income, optional Saved
2. Label (type/label-sm) over amount (type/amount/lg)
3. Hairline dividers between cells
4. Caption: the active filter in words ('Food · October')

**States:** Default · Loading (skeleton amounts) · Empty filter (₹0 with 'No transactions match')

**Rule:** Always the exact sum of the visible rows, never a separate API figure.

## Decisions to defend in a portfolio review

1. **The proof is measured, not described.** Each screen runs a live token audit in the browser: every rendered colour and font size is read back and matched against the token set. The first audit run (before this stage) found two hard-coded colours (white on destructive buttons, the snackbar action blue) and two off-scale sizes in the gauge; all four became tokens or moved onto the scale. 'Built only from the system' is a claim reviewers hear constantly; showing the audit counts is how you make it believable.
2. **Gaps were promoted to components, not patched into screens.** Four things the screens needed didn't exist: an insight card, an upcoming-bill row, a sync status line and a period summary. Each one is specified like the Stage 2 components (anatomy, states, rules) and built from existing tokens, with no new colours or sizes. A system that admits its gaps, and closes them without inventing new tokens, shows that the foundations were general enough.
3. **Home leads with the gauge, not a greeting or a balance.** Most finance home screens open with 'Hi, Ira' and an account balance, which tells you what you have, not what you can spend. Headroom's Home opens with the month as the title and the clearance gauge as the hero, then orders everything below by what needs attention: an insight, the riskiest budgets, bills due, then recent activity. Every section answers 'what should I know or do next?', which is the screen's job.
