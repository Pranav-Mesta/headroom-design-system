# Headroom Design System · Stage 2: Components

> Generated by `tools/build_tokens.py` from `tools/components_spec.py` and this template. Edit those, never the output.
> All example data is synthetic. Live specimens of every component: `site/components.html`.

## How to read this stage

35 components, built only from Stage 1 tokens plus the component sizes below. Each spec lists **anatomy, variants, sizes, every state, accessibility, and do's and don'ts**, then the tokens it consumes. Tokens are named exactly as they appear in Figma variables, so a component's spec doubles as its Figma build checklist.

**Three rules apply to every component, so they aren't repeated in each spec:**

1. **Touch targets are 48×48 minimum** (`size/touch-target/min`), even when the visible control is smaller.
2. **Focus is always visible:** a 2px `color/border/focus` ring with a 2px offset, shown on keyboard focus only (`:focus-visible`), following the component's radius.
3. **Meaning is never color-only:** every state that changes color also changes an icon, a sign, a weight or a word (Stage 1 §1.4).

**About the eight states.** The brief asks for default, hover, focus, pressed, disabled, loading, error and empty on every component. Where a state can't happen (a badge can't be pressed), the table says so with "—" rather than inventing one. Hover exists only on web; touch platforms skip it.

**Platform mapping.** Components marked as native (toggle, segmented control, nav bar, app bar, back gestures, date picker) are implemented with the platform's own control (UISwitch, Material Switch, UITabBar, NavigationBar…) and themed with these tokens. Headroom brands the layer the platforms leave open (color, type, shape, motion) and doesn't reinvent controls people already know.

## Basics

### Button

Starts an action. One primary button per screen at most, so the main path is never ambiguous.

**Anatomy**

1. Container (fill or outline)
2. Label (type/label-lg, sentence case, verb first)
3. Optional leading icon (icon/size/sm)
4. Optional trailing spinner (loading only)

**Variants**

| Variant | Use |
|---|---|
| Primary | The single main action on a screen: Save, Add expense. Fill color/action/primary, label color/action/on-primary. |
| Tonal | Secondary actions that still matter: Add note, Split. Fill color/action/secondary. |
| Outline | Alternatives beside a primary: Cancel, Skip. 1px color/border/default, transparent fill. |
| Ghost | Low-emphasis actions in dense areas and toolbars. No container until hover or press. |
| Destructive | Irreversible removal only: Delete account. Fill color/status/danger, white label. Never a default focus target. |

**Sizes**

| Size | Spec |
|---|---|
| lg | size/control/lg 56 · full-width bottom CTA on mobile |
| md | size/control/md 48 · default |
| sm | size/control/sm 36 visual, 48 hit area · web tables, inline actions |

**States**

| State | Treatment |
|---|---|
| Default | As per variant. |
| Hover (web) | Primary → color/action/primary-hover; others add color/overlay/hover. motion/duration/fast. |
| Focus | 2px color/border/focus ring, 2px offset. Visible on keyboard focus only (:focus-visible). |
| Pressed | Primary → color/action/primary-pressed; others add color/overlay/pressed. Scale 0.98 within 120ms. |
| Disabled | Avoided by policy (see a11y). When unavoidable: color/surface/sunken fill, color/text/disabled label, plus a visible reason below. |
| Loading | Label stays, spinner replaces the leading icon, width locked so the layout doesn't jump; aria-busy=true; repeat taps ignored. |
| Error | Buttons have no error state; the error belongs to the field or a toast that explains what failed. |
| Empty | — |

**Accessibility**

- Minimum 48×48 hit area, even for sm.
- Prefer enabled buttons that validate on tap and explain what's missing. Disabled buttons can't be focused, give no reason, and fail contrast by design.
- Icon-only buttons are a separate component (Icon button) and require an accessible name.
- Loading announces via aria-live: 'Saving…' then 'Saved'.

**Do and don't**

| Do | Don't |
|---|---|
| ✅ Name the outcome: 'Add ₹386 expense' beats 'Submit'. | ❌ Two primary buttons side by side. |
| ✅ Pin the primary action to the bottom on mobile, within thumb reach. | ❌ Use Destructive for reversible actions; offer Undo instead. |

**Tokens:** `color/action/*` · `color/status/danger` · `type/label-lg` · `radius/md` · `size/control/*` · `motion/duration/fast`

### Icon button

A compact action whose icon is universally understood: close, back, more, show/hide balance.

**Anatomy**

1. 48×48 hit area
2. 40×40 visual container (radius/full)
3. Icon (icon/size/md)
4. Optional badge dot

**Variants**

| Variant | Use |
|---|---|
| Standard | No container at rest. App bars, card corners. |
| Tonal | color/action/secondary container. Floating actions on content. |
| Toggle | Two icons for two states, e.g. eye / eye-off for hide balance; uses aria-pressed. |

**Sizes**

| Size | Spec |
|---|---|
| md | 40 visual / 48 hit · default |
| sm | 32 visual / 48 hit · inside inputs (clear, show password) |

**States**

| State | Treatment |
|---|---|
| Default | Icon color/text/secondary; color/text/primary when it's the main control. |
| Hover (web) | color/overlay/hover circle. |
| Focus | 2px focus ring on the 40px circle. |
| Pressed | color/overlay/pressed circle. |
| Disabled | Icon color/text/disabled; prefer hiding the control if it can never act. |
| Loading | Icon swaps to a 20px spinner. |
| Error | — |
| Empty | — |

**Accessibility**

- Always has an accessible name (aria-label / contentDescription) that names the action: 'Hide balances', not 'Eye'.
- Toggle variant exposes state: aria-pressed / 'selected'.
- Show a tooltip on web hover and long-press on touch.

**Do and don't**

| Do | Don't |
|---|---|
| ✅ Use only for actions with an obvious icon. | ❌ Use icon buttons for primary actions on a screen. |
| ✅ Keep the 48px hit area even when the visual is 32. | ❌ Invent icons for abstract actions like 'reconcile'; use a text button. |

**Tokens:** `color/text/secondary` · `color/overlay/*` · `radius/full` · `icon/size/md` · `size/touch-target/min`

### Text input

Single-line free text: merchant name, note, goal name, search within a sheet.

**Anatomy**

1. Label above the field (type/label-md), always visible
2. Container (color/surface/sunken, radius/md, 1px color/border/default)
3. Value (type/body-lg)
4. Optional leading icon / trailing action (clear, show)
5. Helper or error text (type/body-sm)
6. Optional character counter

**Variants**

| Variant | Use |
|---|---|
| Default | Labelled field. |
| With leading icon | Merchant (store icon), search. |
| Multiline | Notes; grows to 4 lines, then scrolls. |

**Sizes**

| Size | Spec |
|---|---|
| md | size/control/md 48 · default |
| lg | 56 · onboarding, single-field sheets |

**States**

| State | Treatment |
|---|---|
| Default | 1px color/border/default; placeholder color/text/secondary. |
| Hover (web) | Border darkens to color/text/secondary. |
| Focus | 2px color/border/focus border (inset, no layout shift); label turns color/action/primary. |
| Pressed | Same as focus (touch). |
| Disabled | color/surface/sunken, no border, value color/text/disabled. Read-only fields stay readable instead. |
| Loading | Trailing 16px spinner, e.g. while checking a UPI ID. |
| Error | 2px color/status/danger border, alert icon + message below in color/status/danger. Message replaces helper text. |
| Empty | Placeholder shows a real example ('Swiggy'), never repeats the label. |

**Accessibility**

- Label is a real <label> / accessibilityLabel; placeholder is never the label.
- Error is tied with aria-describedby and announced; the field also gets aria-invalid.
- Validate on blur or submit, never on every keystroke.
- Keep the text at 16px or more on web so iOS Safari doesn't zoom.

**Do and don't**

| Do | Don't |
|---|---|
| ✅ Put the label above the field so it stays visible while typing. | ❌ Floating labels that shrink into the border; they cut contrast and cause motion. |
| ✅ Write errors that say how to fix it: 'Add a name so you can find this later'. | ❌ Red borders without a message. |

**Tokens:** `color/surface/sunken` · `color/border/default` · `color/border/focus` · `color/status/danger` · `type/body-lg` · `type/label-md` · `radius/md`

### Amount input

Entering money: an expense, a budget limit, a goal target. The most-used input in the product, so it gets its own component.

**Anatomy**

1. Fixed ₹ prefix (type/amount/lg at 70%, raised)
2. Value (type/amount/hero or type/amount/lg, tabular)
3. Live grouping in Indian format as you type (1,00,000)
4. Helper line: context such as '₹1,800 left in Food'
5. Error line

**Variants**

| Variant | Use |
|---|---|
| Hero | Add expense sheet: centred, type/amount/hero, opens the custom keypad (see Keypad). |
| Inline | Inside forms (budget limit, goal target): left-aligned, 48px tall field, uses system decimal keyboard. |
| Compact | Split amounts, filters: type/amount/md. |

**Sizes**

| Size | Spec |
|---|---|
| hero | 48/52 value |
| inline | size/control/md 48 |
| compact | 36 visual / 48 hit |

**States**

| State | Treatment |
|---|---|
| Default | Shows ₹0 in color/text/secondary until the first digit. |
| Hover (web) | As Text input. |
| Focus | Caret after the last digit; inline variant shows the focus border; hero variant shows the keypad. |
| Pressed | — |
| Disabled | Value color/text/disabled; used only for locked amounts such as imported bank transactions, with a lock icon and reason. |
| Loading | While converting currency or fetching a bank amount, a skeleton bar replaces the value. |
| Error | Message below in color/status/danger with an icon: 'Enter an amount above ₹0', 'That's more than ₹10,00,000; check the number'. Value stays editable. |
| Empty | ₹0 placeholder; Save stays enabled and explains 'Enter an amount' if tapped. |

**Decimal handling and validation**

- Rupees are default; paise allowed up to 2 decimals, typed with the '.' key. A third decimal is ignored, not an error.
- Grouping is re-applied on every keystroke and the caret is kept after the digit just typed.
- Pasted text is sanitised: '₹ 1,250.00', '1250', 'Rs.1250/-' all become 1,250.
- Leading zeros are dropped ('007' → 7); '.' first becomes '0.'.
- Hard limit ₹99,99,99,999.99; soft warning above ₹10,00,000 because most extra zeros are typos.
- Stored as integer paise, never a float.

**Accessibility**

- Read as currency: 'eighteen thousand four hundred fifty rupees', not 'one eight comma four five zero'. Set the accessibility value from the formatted number.
- Inline variant uses inputmode='decimal' so phones show a number pad.
- The ₹ prefix is aria-hidden; the label says 'Amount in rupees'.

**Do and don't**

| Do | Don't |
|---|---|
| ✅ Show what the amount means in context ('₹1,800 left in Food after this'). | ❌ Use type=number on web: it allows 'e', loses grouping and scroll-wheel changes values. |
| ✅ Keep the ₹ visually lighter than the number. | ❌ Block typing with an error; let people type, then explain. |

**Tokens:** `type/amount/hero` · `type/amount/lg` · `color/text/primary` · `color/text/secondary` · `color/status/danger` · `radius/md`

### Dropdown / select

Choosing one option from a list that's too long for chips or a segmented control: account, currency, repeat frequency.

**Anatomy**

1. Label
2. Field showing the selected value + chevron-down
3. Options surface: bottom sheet on mobile, popover menu on web
4. Option rows with a check on the selected one

**Variants**

| Variant | Use |
|---|---|
| Standard | Up to ~12 options. |
| Searchable | More than 12 options (bank list): sheet opens with a search field focused. |
| Native | Date-like or OS-standard choices may use the platform picker. |

**Sizes**

| Size | Spec |
|---|---|
| md | 48 field, 56 option rows on mobile, 40 on web menus |

**States**

| State | Treatment |
|---|---|
| Default | As Text input; chevron color/text/secondary. |
| Hover (web) | Border darkens. |
| Focus | Focus border; Enter/Space opens. |
| Pressed | Sheet or menu opens; chevron rotates 180° in motion/duration/base. |
| Disabled | As Text input. |
| Loading | Options area shows 3 skeleton rows. |
| Error | As Text input: 'Choose an account'. |
| Empty | Sheet shows 'No accounts yet' with an 'Add account' action, never an empty list. |

**Accessibility**

- Web: follows the ARIA combobox/listbox pattern; arrow keys move, Escape closes and returns focus to the field.
- Mobile: the sheet is a modal with its title read first.
- Selected option announced as 'selected'.

**Do and don't**

| Do | Don't |
|---|---|
| ✅ Use a bottom sheet on phones; it's thumb-reachable and shows more options. | ❌ Use a dropdown for 2–4 options; use a segmented control or chips. |
| ✅ Pre-select the most likely value (the account used last time). | ❌ Put actions (Delete) inside an options list. |

**Tokens:** `color/surface/raised` · `elevation/2` · `elevation/3` · `radius/md` · `type/body-lg`

### Checkbox

Selecting any number of independent options: multi-select transactions, onboarding categories, consent.

**Anatomy**

1. 20×20 box (radius/xs), 48×48 hit area
2. Check or dash glyph
3. Label to the right (type/body-lg)
4. Optional supporting text

**Variants**

| Variant | Use |
|---|---|
| Unchecked | 2px color/border/default outline. |
| Checked | color/action/primary fill, white check. |
| Indeterminate | Dash: 'select all' when some rows are selected. |

**Sizes**

| Size | Spec |
|---|---|
| md | 20 box / 48 row |

**States**

| State | Treatment |
|---|---|
| Default | As variant. |
| Hover (web) | color/overlay/hover circle behind the box. |
| Focus | Focus ring around the box. |
| Pressed | color/overlay/pressed circle; check draws in motion/duration/fast. |
| Disabled | color/text/disabled outline and label; supporting text explains why. |
| Loading | — |
| Error | Box outline and message in color/status/danger: 'Accept the terms to continue'. |
| Empty | — |

**Accessibility**

- The whole row (box + label) is the tap target.
- Indeterminate exposes aria-checked='mixed'.
- Checked state isn't color-only: the glyph carries it.

**Do and don't**

| Do | Don't |
|---|---|
| ✅ Use for settings that apply only when saved. | ❌ Use a checkbox for an instant on/off setting; that's a Toggle. |
| ✅ Write labels as positive statements. | ❌ Negative labels ('Don't send me emails'). |

**Tokens:** `color/action/primary` · `color/border/default` · `radius/xs` · `size/touch-target/min`

### Radio

Choosing exactly one of 2–6 visible options where each needs explanation: budget period, rounding rule.

**Anatomy**

1. 20px ring, 48px hit area
2. 10px inner dot when selected
3. Label
4. Optional description

**Variants**

| Variant | Use |
|---|---|
| List | Stacked rows, default. |
| Card | Option as a selectable card with description, used in onboarding (e.g. 'Monthly from payday' vs 'Calendar month'). |

**Sizes**

| Size | Spec |
|---|---|
| md | 20 ring / 48 row; card variant min 72 |

**States**

| State | Treatment |
|---|---|
| Default | 2px color/border/default ring. |
| Hover (web) | Overlay circle. |
| Focus | Ring on the group's selected item; arrow keys move selection. |
| Pressed | Overlay; dot scales in over motion/duration/fast. |
| Disabled | Muted ring and label with a reason. |
| Loading | — |
| Error | Group message: 'Choose how your month starts'. |
| Empty | No option pre-selected only when there's no sensible default. |

**Accessibility**

- Wrapped in a radiogroup with a visible group label.
- Arrow keys move within the group; Tab leaves it.
- Selected card variant also gets a 2px color/action/primary border and check icon, not just a tint.

**Do and don't**

| Do | Don't |
|---|---|
| ✅ Show all options at once when people need to compare them. | ❌ Use radios for more than ~6 options; use a select. |
| ✅ Pre-select the recommended option. | ❌ Mix radios and checkboxes in one list. |

**Tokens:** `color/action/primary` · `color/border/default` · `radius/full` · `radius/lg`

### Toggle

An instant on/off setting that takes effect immediately: hide balances, budget alerts, biometric lock.

**Anatomy**

1. 52×32 track (radius/full)
2. 24px thumb
3. Optional check icon in the thumb when on
4. Label left, toggle right, on one row

**Variants**

| Variant | Use |
|---|---|
| Standard | iOS renders as UISwitch and Android as Material Switch, both themed with these tokens. |

**Sizes**

| Size | Spec |
|---|---|
| md | 52×32 track / 48 row min |

**States**

| State | Treatment |
|---|---|
| Default off | Track color/surface/sunken with 2px color/border/default; thumb color/text/secondary. |
| Default on | Track color/action/primary; thumb white with a check icon. |
| Hover (web) | Overlay on the thumb. |
| Focus | Focus ring around the track. |
| Pressed | Thumb widens 4px; slides in motion/duration/base, motion/easing/standard. |
| Disabled | Muted track and thumb plus a reason ('Turn on notifications in Settings'). |
| Loading | Thumb shows a spinner while a server setting saves; reverts with a toast if it fails. |
| Error | Reverts to the previous state and a snackbar explains why. |
| Empty | — |

**Accessibility**

- role='switch' with aria-checked; the label is the switch's name.
- The on state carries an icon in the thumb, not color alone.
- Never use a toggle inside a form that needs Save.

**Do and don't**

| Do | Don't |
|---|---|
| ✅ Label the setting, not the action: 'Budget alerts'. | ❌ Use a toggle for choices that need a Save button. |
| ✅ Apply immediately and confirm with a short snackbar only if it's not visible. | ❌ Write 'On/Off' text next to it; the switch already says that. |

**Tokens:** `color/action/primary` · `color/surface/sunken` · `color/border/default` · `radius/full` · `motion/duration/base`

### Segmented control

Switching between 2–4 views of the same content: Week / Month / Year, Expense / Income.

**Anatomy**

1. Track (color/surface/sunken, radius/md, 3px padding)
2. Segments with labels (type/label-md)
3. Selected thumb (color/surface/raised, elevation/1)

**Variants**

| Variant | Use |
|---|---|
| Text | Default. |
| Icon + text | Expense / Income with arrow icons. |

**Sizes**

| Size | Spec |
|---|---|
| md | 40 visual / 48 hit |
| sm | 32 visual / 48 hit · web filters |

**States**

| State | Treatment |
|---|---|
| Default | Unselected labels color/text/secondary. |
| Hover (web) | Overlay on the segment. |
| Focus | Focus ring around the focused segment. |
| Pressed | Thumb slides to the segment in motion/duration/base. |
| Disabled | Whole control muted; a single disabled segment is not allowed, so remove it instead. |
| Loading | Content below loads; the control stays usable. |
| Error | — |
| Empty | — |

**Accessibility**

- Exposed as a tab list (when it swaps views) or a radio group (when it sets a value).

- Labels stay short enough not to truncate at 200% text size; wrap to a select if they do.

**Do and don't**

| Do | Don't |
|---|---|
| ✅ Use for mutually exclusive views of the same data. | ❌ Use for navigation between unrelated screens; use tabs or the nav bar. |

### Chips and tags

Filters, quick choices and labels: filter transactions by category, pick a suggested amount, tag a transaction.

**Anatomy**

1. Container (radius/full, 32 visual / 48 hit)
2. Optional leading icon or category dot
3. Label (type/label-md)
4. Trailing × on removable input chips

**Variants**

| Variant | Use |
|---|---|
| Filter | Toggles a filter; selected gets color/action/secondary fill + check icon. |
| Choice | Single choice among suggestions: ₹100 / ₹500 / ₹1,000. |
| Input | Removable values the user added: tags. |
| Tag (static) | Read-only label on a row: 'Recurring', 'Split'. Uses color/surface/sunken, type/label-sm. |

**Sizes**

| Size | Spec |
|---|---|
| md | 32 visual / 48 hit |
| sm (tag) | 24 visual, not interactive |

**States**

| State | Treatment |
|---|---|
| Default | 1px color/border/subtle outline, color/text/primary label. |
| Hover (web) | Overlay. |
| Focus | Focus ring. |
| Pressed | Overlay; selection applies immediately. |
| Disabled | Muted; prefer removing the chip. |
| Loading | Results under the chips update; chip itself does not spin. |
| Error | — |
| Empty | A filter row with no results shows the empty state below, with 'Clear filters'. |

**Accessibility**

- Filter chips are toggle buttons with aria-pressed; selected also shows a check icon.
- Removable chips: the × has its own label 'Remove tag Travel'.
- Chip rows scroll horizontally with visible overflow, never a hidden cut-off.

**Do and don't**

| Do | Don't |

## Decisions to defend in a portfolio review

1. **Budgets show room left, and overspend runs past a line instead of turning red.** The budget bar and balance card draw the limit as a dashed clearance line and fill toward it. Going over is shown as the fill crossing that line, with the amount over in words, rather than recoloring the whole bar red or capping at 100%. It keeps the Stage 1 principle (clarity before alarm) inside the most-seen component, and the overflow carries real information: how far over, at a glance. Thresholds are global (80% near, 100% over), so the colors mean the same thing on every screen.
2. **Buttons stay enabled; they explain instead of greying out.** Disabled buttons can't receive focus, don't say why they're disabled and are low-contrast by design (WCAG exempts them, which is the problem). Headroom keeps Save enabled and, on tap, focuses the first missing field with a message ('Enter an amount'). It's the approach GOV.UK and Material's form guidance recommend, and it's testable: every button is reachable and every failure has words.
3. **Undo instead of 'Are you sure?' for reversible actions.** Deleting a transaction or archiving a budget shows a snackbar with Undo for 8 seconds; the data is soft-deleted. Confirmation dialogs train people to tap 'Yes' without reading, and in a money app that ritual adds friction to the most common clean-up tasks. Modal confirmation is reserved for irreversible actions (delete account, remove a bank connection), where it means something.
